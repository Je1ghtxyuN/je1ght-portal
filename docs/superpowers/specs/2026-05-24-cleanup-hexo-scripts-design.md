# Cleanup Hexo Scripts — Spec

## Goal

Remove dead code and redundant scripts from `apps/blog-portal/scripts/` so the
architecture is clear: one control path per page, no confusing overlaps.

## Background

The scripts directory had two redundant patterns:

1. **Homepage double-control**: `portal-home-generator.js` (generator) and
   `portal-home-tag.js` (tag plugin) both try to render the custom homepage.
   The generator always wins — it directly sets `path: 'index.html'` with
   `renderHome()` output. The tag plugin is never invoked in practice.

2. **Dead tags**: `portal_blog` and `portal_study_room` were registered in
   `portal-tags.js` but are not referenced by any source page. Study-app was
   separated into its own repository on 2026-05-16.

## Changes

### DELETE: `scripts/portal-home-tag.js`

Registers `{% portal_home %}` tag. The homepage is controlled by
`portal-home-generator.js` which sets page content directly via
`hexo.extend.generator.register()`. The tag is never reached.

### EDIT: `scripts/portal-tags.js`

Remove two tag registrations:

```diff
-hexo.extend.tag.register('portal_blog', () => portalRenderer.renderBlog())
 hexo.extend.tag.register('portal_portfolio', () => portalRenderer.renderPortfolio())
 hexo.extend.tag.register('portal_about', () => portalRenderer.renderAbout())
-hexo.extend.tag.register('portal_study_room', () => portalRenderer.renderStudyRoom())
 hexo.extend.tag.register('portal_contact', () => portalRenderer.renderContact())
```

Keep: `portal_portfolio`, `portal_about`, `portal_contact` (all actively used
by corresponding `source/<page>/index.md` files).

### EDIT: `scripts/portal-renderer.js`

Remove two render functions that are no longer called:

- `renderBlog(locals)` (~60 lines, renders post list as portal-page cards)
- `renderStudyRoom()` (study-app was separated, no content to render)

Also remove `renderBlog` and `renderStudyRoom` from the returned object.

### EDIT: `source/index.md`

Replace `{% portal_home %}` with a comment explaining the generator controls
the homepage. Keep frontmatter minimal — generator overrides it anyway.

```markdown
---
title: Home
comments: false
date: 2025-06-25 00:00:00
---

<!-- Homepage HTML is generated by scripts/portal-home-generator.js.
     This file exists as a placeholder; the generator sets type, layout,
     and content at build time. -->
```

## Not Changing

| File | Rationale |
|------|-----------|
| `portal-home-generator.js` | Core homepage mechanism |
| `portal-tags.js` (remaining tags) | In use by about/contact/portfolio pages |
| `portal-data-sync.js` | Injects i18n config, syncs nav/theme from YAML |
| `portal-shared-config.js` | Shared config loader, depended on by others |
| `auto-date.js` | Independent utility, sets dates on posts |
| npm scripts `home:custom` / `home:default` | Keep for occasional testing |
| `scripts/_disabled/` directory | Archive location for disabled scripts |

## Verification

1. `rm -rf db.json public && npx hexo generate` — builds without errors
2. `grep` output of `public/index.html` — contains `portal-home` marker
3. `npm run home:default && npx hexo generate` — produces Butterfly default index
4. `npm run home:custom && npx hexo generate` — restores custom template
5. All other pages (about, contact, portfolio) render correctly after build
